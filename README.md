# CS 255 DriverPass System Analysis and Design

## Project Summary

DriverPass was the client for this project. The company wanted a secure, cloud-based web system that would help students prepare for DMV driving examinations through online coursework, practice tests, and in-person driving lessons. The system was designed to support customer registration, training packages, lesson scheduling, progress tracking, employee access, reporting, and DMV information updates.

## What I Did Well

I believe I did particularly well translating DriverPass's business needs into specific system requirements. I identified both functional and nonfunctional requirements, including role-based access, reservation conflict prevention, security, responsive browser access, reporting, and system performance. I also represented these requirements visually through use case, activity, sequence, and class diagrams in the system design document.

## What I Would Improve

If I revised one part of the project, I would further refine the UML diagrams. I would review relationships, cardinalities, labels, and interactions to make them as consistent and easy to interpret as possible. This would improve communication between developers, stakeholders, and other people who may use the design as a reference during implementation.

## Interpreting User Needs

I interpreted the user's needs by identifying what each DriverPass user needed to accomplish and converting those needs into system functions. For example, customers need to schedule lessons and take practice tests, instructors need access to assigned lessons and student information, the owner needs reports, and the IT administrator needs account and permission controls. Considering user needs is important because a technically functional system is only successful if it solves the client's actual problems and provides users with appropriate, efficient, and secure access to the functions they require.

## My Software Design Approach

My approach to software design is to begin by understanding the client's goals, users, constraints, and requirements before designing the technical solution. I then separate the requirements into functional and nonfunctional categories and use UML diagrams to model how users, processes, system components, and data interact. In future projects, I would continue using requirements analysis, use cases, activity diagrams, sequence diagrams, class diagrams, and iterative review with stakeholders to validate the design before development begins.
